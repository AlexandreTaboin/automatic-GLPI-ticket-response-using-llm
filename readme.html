Version 4.17 — un modèle, en local

Relais répond aux tickets GLPI

Un script PowerShell lit les tickets ouverts, consulte votre base de connaissance et votre documentation, puis rédige un suivi. L'inférence reste sur Ollama. Aucun ticket n'est envoyé à un service cloud.

01

Ce que fait le script

🎫

Tickets

Lecture, priorité, type, catégorie ITIL, suivi public et suivi privé. Le ticket traité reçoit le type de demande ProcessedMarker.

📚

Base GLPI

À chaque ticket, Relais parcourt les articles KnowbaseItem et ne garde que ceux qui correspondent. Myrtille peut suivre cette procédure.

📁

Documentation

Word, PDF, Excel, PowerPoint, texte et images dans un dossier. Les photos de ticket passent par un modèle vision.

🔍

Web local

SearXNG, sur votre machine. Utile pour nommer une alerte. Myrtille ne copie pas une procédure trouvée en ligne.

🗓️

Agenda et Teams

Optionnels. Un rendez-vous n'est créé que si un technicien appelle Myrtille. Le secret d'application Graph ne poste pas dans Teams.

🔒

Rien ne sort

Ollama et SearXNG écoutent en local. Le dépôt ne contient que des jetons d'exemple. DryRun est activé à la livraison.

02

Deux voix, un seul modèle

Il n'y a plus trois Modelfiles. AgentModel vaut qwen3.5:9b. Le modèle appelle des outils. Deux voix écrivent dans GLPI.

Myrtille — suivi public

Elle parle à l'utilisateur. Elle se présente une fois comme une IA, puis elle rassure, elle qualifie, et elle ne donne une marche à suivre que si elle vient de votre base ou de votre documentation.

  • Elle ne cite ni l'article, ni le fichier, ni les outils.
  • Elle ne propose pas de rendez-vous.
  • Hors de la liste autorisée, elle escalade.

Perceval — suivi privé

Il parle aux techniciens. Un diagnostic probable, deux pistes, une priorité, une catégorie. Il peut citer le titre d'un article ou le nom d'un fichier.

  • Pas de pas-à-pas destiné à l'utilisateur.
  • Le second compte GLPI (GlpiAideToken) porte cette voix.

04

Le savoir qu'elle consulte

Relais ne colle pas toute la base dans le prompt. Le modèle accepte souvent 256 000 tokens. Le script fixe NumCtx à 16 384. C'est assez pour le prompt, quatre articles et plusieurs tours d'outils. Au-delà, un serveur sans GPU ralentit sans gain.

SourceOùRôle
Base GLPIKnowbaseItemConsultée à chaque ticket. Jusqu'à 4 articles dont le texte colle au problème.
DocumentationInternalDocsPathpdf, docx, xlsx, pptx, odt, odp, txt, csv, md, rtf, html, images. Les .doc, .xls et .ppt sont à convertir.
Mémosrelais-memos.jsonFiches tirées des tickets clos, puis publiées dans la base. Une fiche déjà publiée n'est plus lue en double.
Visionqwen2.5vl:7bDécrit une photo jointe. Facultatif.

Ce qui n'est pas retenu

Une arrivée d'agent est un cas particulier, pas une procédure. Une alerte de blocage antivirus répétée non plus : cinquante fiches « exception ou quarantaine » pousseraient Myrtille à proposer une liste blanche. Le script ignore ces deux sujets. -PurgeExcludedMemos retire celles déjà publiées.

Sont gardées les pannes qui décrivent un incident réel : antivirus qui ne s'installe pas, licence périmée, application inaccessible après un changement de produit.

PowerShell
# Publie les fiches locales dans la base. Reprise possible.
powershell.exe -File .\Myrtille.ps1 -MigrateMemosToKb

# Retire arrivées d'agents et alertes antivirus répétitives.
powershell.exe -File .\Myrtille.ps1 -PurgeExcludedMemos

06

Configuration

PowerShell
GlpiApiUrl         = 'https://glpi.exemple.local/apirest.php'
GlpiAppToken       = 'VOTRE_APP_TOKEN'
GlpiUserToken      = 'VOTRE_USER_TOKEN'
GlpiAideToken      = 'VOTRE_USER_TOKEN_AIDE'
ProcessedMarker    = 8
AgentModel         = 'qwen3.5:9b'
NumCtx             = 16384
InternalDocsPath   = 'C:\Scripts\Docs'
DryRun             = $true
DevMode            = $false
EnableCalendar     = $false
EnableTeams        = $false
DevMode rend le journal très verbeux, y compris le contenu des appels. Laissez-le à $false sur une machine partagée.

À adapter chez vous

Get-XdematAppCatalog et Get-ItilKeywordHint proposent des chemins ITIL (logiciels métier, messagerie, antivirus). Remplacez-les par l'arbre de votre GLPI. Le repère formulaire.exemple.fr/todos dans Test-IsOnboardingTicket est un exemple.

EnableCalendar et EnableTeams valent $false. Le script répond aux tickets sans Microsoft 365. Les GUID et le secret du fichier sont des placeholders.

Inscription d'application Entra, permissions application Calendars.Read et Calendars.ReadWrite, puis tenant, client, secret et UPN de l'organisateur. Un rendez-vous n'est créé que sur un message de technicien, pas sur un ticket neuf.

Flux clients publics, permissions déléguées Chat.ReadWrite, User.Read, offline_access, puis -TeamsLogin et l'identifiant du chat. Le secret d'application ne peut pas envoyer de message.

Lancer

PowerShell
# GLPI, Ollama, SearXNG
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Myrtille.ps1 -Test

# Savoir trouvé pour un ticket. N'écrit rien.
powershell.exe -File .\Myrtille.ps1 -PreviewKnowledge 1234

# Un ticket. Respecte DryRun.
powershell.exe -File .\Myrtille.ps1 -TicketId 1234

# Un cycle, pour le planificateur de tâches
powershell.exe -File .\Myrtille.ps1 -Once
InterrupteurEffet
-BuildMemosRésume des tickets clos en fiches. Ignore arrivées et alertes antivirus répétitives.
-MigrateMemosToKbPublie les fiches dans la base. Une fiche avec kb_id n'est pas recréée.
-ClassifyOpen / -ClassifyClosedRecalcule type et catégorie, sans suivi Myrtille.
-DumpTicketExporte un ticket pour relecture. N'écrit pas dans GLPI.
-TeamsLoginConnecte une fois le compte Office de Myrtille.

Le journal indique prompt=…/16384. Au-dessus de 85 %, les tours suivants peuvent oublier le début du prompt.

08

Sécurité

Ne commitez jamais les jetons, le journal, relais-*.json ni le dossier de documentation. Le .gitignore les exclut. Un secret déjà poussé se révoque dans GLPI ou Entra : l'effacer du fichier ne suffit pas.
  • Les fichiers dont le nom contient token, secret, password, credential ou apikey ne sont pas indexés.
  • Les mémos passent par un filtre qui retire e-mail, téléphone et adresse IP. Ce filtre n'est pas parfait : relisez une fiche avant de la considérer comme anonyme.
  • Passez DryRun à $false seulement après un -PreviewKnowledge et un -TicketId concluant.
Plusieurs centaines de fiches dépassent largement 16 384 tokens. Les injecter toutes rend chaque ticket lent, surtout sans GPU, et noie la bonne procédure. Relais cherche, puis ne garde que les articles proches.
C'était la version 2 : trois modèles spécialisés. Relais 4 n'en a plus besoin. Un modèle avec outils lit le ticket, cherche, classe et rédige. Les Modelfiles ne sont plus livrés.
Myrtille n'a le droit de détailler une manipulation que si elle est dans la base, dans la documentation, ou dans une courte liste (redémarrer, câble, Wi-Fi, son, session Windows). Le reste est une escalade, sans étape inventée. Le web sert à expliquer, pas à copier un mode d'emploi.
